# RentMont

Монитор аренды **квартир** на Sreality.cz: **Brno-město**, аренда **строго < 13 500 Kč/мес.**, проверка каждые **10 минут**. Коммунальные в порог не входят. Только квартиры целиком: обязательный фильтр `is_room_rent=false`. Комнаты исключаются. Если нужен бюджет вместе с коммунальными — фильтрацию нужно изменить.

## Запуск

Python 3.10+:

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
pip install -e .
```

Скопируй `.env.example` в `.env` и заполни:

- `OPENAI_API_KEY` — ключ OpenAI, требуется доступ к API и баланс (подписка ChatGPT его не заменяет).
- `TELEGRAM_BOT_TOKEN` — токен бота от `@BotFather`.
- `TELEGRAM_CHAT_ID` — ID своего чата или группы. Сначала отправь боту `/start`. ID можно получить через метод Telegram Bot API `getUpdates`; для группы добавь бота и отправь сообщение. Не публикуй URL с токеном.

```bash
rentmont --once                   # одна проверка
rentmont                          # постоянный мониторинг
python -m rentmont                # альтернативный запуск
python -m unittest discover -s tests -v  # тесты без ключей и сети
```

Процесс должен оставаться запущенным. Для круглосуточной работы используй VPS/systemd или Windows Task Scheduler с запуском при загрузке. Запускай только один экземпляр на один `DATA_DIR`.

## Хранилище

`data/db.json` — единственный источник состояния: обработанные ID, данные объявлений, признак первой проверки и очередь уведомлений. SQLite не используется. Файл создаётся автоматически:

```json
{
  "schema_version": 1,
  "initialized": false,
  "ads": {},
  "excluded_ids": [],
  "parsed_results": {}
}
```

После обработки `ads` содержит записи по ID: `title`, `listing` (платежи, ссылка, тип аренды и площадь) и `notified`. `excluded_ids` хранит ID объявлений, не прошедших фильтр. `parsed_results` хранит **каждый успешный LLM-результат** (`result`) и SHA-256 входных полей (`fingerprint`), включая комнаты, неизвестную аренду и превышение бюджета. Кеш записывается сразу после парсинга, до фильтрации и формирования уведомления. При чтении используется Pydantic `model_validate_json`, при записи — `model_dump_json`. Запись идёт во временный файл в том же каталоге с последующей атомарной заменой. Изменения сохраняются после каждого объявления и успешного уведомления. Повреждённый или несовместимый файл останавливает запуск и **не перезаписывается**; ошибка записи останавливает монитор.

Хранилище рассчитано на **один процесс** — межпроцессных блокировок нет. Если ранее использовался `monitor.sqlite3`, автоматической миграции нет: старый файл не изменяется, монитор начинает с новой первой проверки.

## Результат

`data/listings.json` — накопленный архив найденных подходящих объявлений, не список только актуальных:

```json
[
  {
    "rent_kc": 12500,
    "utilities_kc": 4000,
    "comission_kc": null,
    "deposit_kc": 16500,
    "is_room_rent": false,
    "area_m2": 36,
    "available_from": "2026-12-01",
    "distance_to_center_km": 4.9,
    "published_at": "2026-10-01",
    "updated_at": "2026-10-14",
    "photos": [],
    "link": "https://www.sreality.cz/detail/pronajem/byt/1+kk/brno-stary-liskovec-sevastopolska/1858146380"
  }
]
```

`comission_kc` намеренно сохраняет запрошенное написание. Все суммы — в Kč; неизвестные/неоднозначные значения — `null`. Аренда и коммунальные — ежемесячные; комиссия и залог — разовые. Нулевые суммы сохраняются как `null`.

`is_room_rent` — `true`, если категория или текст явно говорят об аренде только комнаты/места; иначе `false`. `area_m2` — площадь, указанная в объявлении, одинаково для комнат и квартир (приоритет: `usable_area`, заголовок, затем `floor_area` или описание); неизвестная — `null`. В монитор проходят только объявления с `is_room_rent=false`. Категория `Pokoj` отсекается до LLM, комнаты из текста — после LLM. Ранее сохранённые комнаты не отправляются и не экспортируются в `listings.json`, но остаются в архиве `db.json`. Площадь выводится рядом с названием в Telegram; `is_room_rent` сохраняется в JSON.

`available_from` — дата заселения: `null` (не указано/по договорённости), `"asap"` (сразу/как можно скорее), либо `"YYYY-MM-DD"` (конкретная дата). Извлекается из описания и `ready_date`; при противоречии приоритет у явного текста описания. Неполные даты без года не угадываются. В Telegram выводится строка `Move In`.

`distance_to_center_km` — расстояние **по прямой** до náměstí Svobody в Брно (49.1951, 16.6080), округлённое до 0,1 км. Вычисляется формулой haversine из `locality.gps_lat/gps_lon`, без LLM и дополнительных API. Отсутствующие/невалидные координаты — `null`; точность зависит от локации Sreality. Это не расстояние по дороге и не время поездки. В Telegram: «Km to Center: ≈4.9 км по прямой».

`published_at` и `updated_at` — даты публикации и последнего редактирования из API `since` и `edited`, без LLM, в формате `YYYY-MM-DD`. Если дата отсутствует или невалидна — `null`. В Telegram выводятся обе даты. Для объявлений, которые всё ещё попадают в текущий поиск, эти даты и другие API-метаданные обновляются при проверках без LLM.

`photos` — до 3 уникальных HTTP(S)-ссылок из `advert_images` API, в исходном порядке. В Telegram одна фотография отправляется через `sendPhoto`, несколько — альбомом через `sendMediaGroup`; компактный текст объявления — в подписи к первому фото (лимит Telegram 1024 символа, название ограничено 180 символами). Название — кликабельная HTML-ссылка; содержимое экранируется. Для старых записей с большим числом фото тоже отправляются только первые 3. Для ссылок CDN `*.sdn.cz` добавляется параметр обработки изображения `fl=res,1200,1200,1|shr,,20|jpg,80`, как на странице Sreality: исходные ссылки API без него могут возвращать HTTP 401. Это применяется и при скачивании фото из старых записей. Монитор сам скачивает JPEG/PNG (до 10 МБ на фото) и загружает их файлами через multipart; для альбома используются `attach://`, поэтому Telegram не скачивает ссылки с CDN Sreality. Если отдельный снимок не скачался или оказался невалидным, он пропускается, остальные отправляются. Фото не передаются в OpenAI. Если пригодных снимков нет или Telegram явно отклоняет медиа (400), отправляется текст. При таймауте или ограничении частоты сообщение остаётся в очереди, без немедленной текстовой подмены.

Формат Telegram (название — ссылка; в `Comission/Deposit` сначала комиссия, затем залог, без вычисления итога; в `Price` добавляется `= сумма`, только если аренда и коммунальные известны):

```text
🏠 Pronájem bytu 1+kk — 36 м²
💰 Price: 12,500 Kč + 4,000 Kč = 16,500 Kč
🔐 Comission/Deposit: не указано + 16,500 Kč
🔑 Move In: 01.12.2026
📍 Km to Center: ≈4.9 км по прямой
🕒 Uploaded 01.10.2026 Updated 14.10.2026
```

Для старых записей без `is_room_rent` категория комнаты определяется по `/byt/pokoj/` в ссылке, иначе используется `false`. Остальные отсутствующие поля читаются со значениями `area_m2=null`, `available_from=null`, `distance_to_center_km=null`, `published_at=null`, `updated_at=null`, `photos=[]`. При первом сканировании после обновления старые результаты становятся кешем без дополнительного вызова LLM; текущие входные данные принимаются за исходный снимок, поскольку прежнего хеша нет. Площадь, заселение и другие LLM-поля восстанавливаются только при последующем изменении входных данных; даты публикации, фото и расстояние обновляются сразу из API.

- Поиск и детали берутся из публичного API Sreality `/api/v1/estates/search` и `/api/v1/estates/{id}`. Используется район `72`; фильтры дополнительно проверяются локально.
- OpenAI получает описание и поля платежей, без контактов продавца и фотографий. Используется structured output; результаты LLM всё равно могут содержать ошибки. Неизвестная аренда не проходит фильтр.
- Каждые 10 минут детали текущих результатов поиска проверяются через Sreality API. Если изменились описание, цена, примечания, площадь, тип или дата заселения — выполняется новый LLM-парсинг. При неизменном хеше используется кеш, даже если результат не прошёл фильтр. Изменение фото, координат или `edited` само по себе не вызывает LLM. Ошибки и отказы LLM не кешируются и повторяются в следующем цикле. Смена модели сама по себе кеш не сбрасывает.
- Уже отправленные объявления обновляются в JSON без повторного уведомления. Ранее отсеянное объявление, ставшее подходящим, может получить первое уведомление. Архив не гарантирует актуальность объявлений, исчезнувших из текущего поиска. В логах выводятся число LLM-вызовов и попаданий в кеш за цикл (внутренние ретраи SDK в счётчик не входят).
- По умолчанию первая успешная проверка сохраняет текущие объявления **без уведомлений**, затем уведомления приходят только о новых. Для уведомлений обо всех объявлениях сразу установи `NOTIFY_EXISTING=true` **до первого запуска**. Первая проверка всё равно расходует OpenAI API на текущие объявления.
- Неудачная обработка повторяется в следующем цикле. Ошибка Telegram оставляет сообщение в очереди. При сетевом таймауте после принятия сообщения Telegram или аварии до записи подтверждения редкие дубли возможны — exactly-once Telegram не предоставляет.
- Частота, район, бюджет и модель настраиваются в `.env`. По умолчанию используется `gpt-5.4-mini`; переопределение — `OPENAI_MODEL`. Полный проход дольше 10 минут сдвинет расписание: проверки не запускаются параллельно.

API Sreality не гарантирован как стабильный публичный контракт: при изменениях сайта может потребоваться адаптация. Соблюдай правила сайта; обход CAPTCHA/ограничений не реализован. Ключи и каталог `data/` исключены из Git.
