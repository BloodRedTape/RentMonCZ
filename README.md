# RentMont

Монитор Sreality.cz: аренда **квартиры целиком** в **Brno-město**, базовая аренда **строго < 13 500 Kč/мес.**, проверка каждые **10 минут**. Коммунальные не входят в порог. Факты извлекаются через **gpt-5.4-mini**, уведомления приходят в Telegram с максимум **3 фото**.

## Запуск

Python 3.10+:

```bash
python -m venv .venv
# PowerShell: .venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
pip install -e .
```

Скопируй `.env.example` в `.env`, заполни `OPENAI_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. Подписка ChatGPT не заменяет оплату OpenAI API. Отправь боту `/start`, прежде чем использовать личный чат.

```bash
python -m rentmont --once
python -m rentmont
# Принудительно повторить извлечение текущих объявлений:
python -m rentmont --once --reextract
```

Без установки пакета: в PowerShell `$env:PYTHONPATH = "$PWD/src"`, затем `python -m rentmont`. В Git Bash/Linux: `PYTHONPATH=src python -m rentmont`.

Процесс должен оставаться запущенным. Для 24/7 используй VPS/systemd или Windows Task Scheduler. **Только один процесс на DATA_DIR**: межпроцессных блокировок нет.

По умолчанию первая успешная проверка сохраняет подходящие объявления как `suppressed`, без Telegram-спама. Для уведомлений сразу установи `NOTIFY_EXISTING=true` до первого запуска. Первичная обработка всё равно расходует OpenAI API.

## Docker

Нужны Docker Engine / Docker Desktop (Linux containers) и Docker Compose v2.
Настройки берутся из `.env`; ключи и локальные данные не копируются в образ.
`./data` подключается в контейнер как `/app/data`, поэтому состояние сохраняется при пересоздании контейнера. `DATA_DIR` внутри Compose фиксирован на `/app/data`.

```bash
docker compose up -d --build
docker compose logs -f --tail=100
docker compose down
```

Приложение работает от root внутри контейнера. В rootless Docker это не root хоста; подключённый каталог `./data` должен быть доступен пользователю, запустившему Docker. В обычном rootful Docker созданные файлы могут принадлежать root хоста.
Не запускай локальный монитор одновременно с контейнером: процесс на каталог данных должен быть один.

Разовая проверка (сначала останови постоянный контейнер):

```bash
docker compose stop rentmont
docker compose run --rm --build rentmont --once
# Принудительное обновление источника и извлечения:
docker compose run --rm rentmont --once --reextract
docker compose up -d
```

После изменения кода пересобери образ: `docker compose up -d --build`.
После изменения `.env` пересоздай контейнер: `docker compose up -d --force-recreate`.
Политика `unless-stopped` перезапускает контейнер после завершения процесса, включая ошибки; причину смотри в логах. Ротация логов ограничена тремя файлами по 10 МБ.

## Разделение ответственности

```text
src/rentmont/
  models.py       # контракты фактов, файлов и общего состояния
  config.py       # настройки из .env
  sreality.py     # внешнее API и адаптер raw → SourceListing
  extraction.py   # whitelist входных полей, OpenAI → RentalDetails
  filters.py      # чистая политика отбора, без сохранения решений
  location.py     # расстояние до центра Брно
  storage.py      # отдельные атомарные файлы на объявление
  service.py      # обновление, отбор, orchestration доставки
  telegram.py     # форматирование, скачивание фото, отправка без доступа к БД
  cli.py          # CLI и расписание
```

`SourceListing` — проекция сырого объявления для фильтрации и отображения. `RentalDetails` — только извлечённые факты: `payments`, `is_room_rent`, `area_m2`, `available_from`. `Listing` — публичная проекция `{source, rental}` для Telegram и экспорта. Составного `ListingRecord` нет.

## Хранение: отдельная папка на объявление

```text
data/
  state.json
  listings.json
  <id>/
    source.json
    extraction.json
    notification.json
```

`state.json` содержит только общее состояние монитора, формат **v4**:

```json
{
  "schema_version": 4,
  "initialized": false,
  "current_search_ids": []
}
```

В папке каждого объявления файлы независимы:

- `source.json`: `{raw, first_seen_at, last_seen_at}`. Полный detail из API, независимо от результата фильтрации. `last_seen_at` — время последнего скачивания detail, не появления в поиске; при обычном цикле файл не обновляется. При принудительном обновлении `first_seen_at` сохраняется.
- `extraction.json`: `{details, extracted_at}`. Успешный результат LLM, включая комнаты, неизвестную аренду и превышение бюджета. Файл отсутствует до первого успешного извлечения.
- `notification.json`: `{status, sent_at}`. Статус `sent` с временем отправки или `suppressed` с `sent_at=null`. Отсутствие файла означает «ещё не уведомляли».

`current_search_ids` обновляется только после успешного завершения поиска. Исчезнувшие объявления остаются в архиве, но не участвуют в текущем экспорте и доставке. Ошибка поиска сохраняет предыдущий набор ID, однако доставка в этом цикле не выполняется.

Каждый файл читается по необходимости и сохраняется атомарно: временный файл записывается и заменяет основной. Обновление источника не перезаписывает извлечение или уведомление. Записи валидируются Pydantic; ID — только цифры и должен совпадать с ID внутри source. При ошибке чтения/сохранения монитор останавливается. Повреждённые файлы не сбрасываются автоматически.

Общей транзакции между файлами нет: после сбоя может остаться source без extraction — следующий цикл закончит обработку. Состояние доставки сохраняется только после успешной отправки. Миграций нет; старый `db.json` не используется. Новые папки заполняются при запуске.

Сырой ответ API может содержать контактные данные: база локальная, `data/` исключён из Git. В OpenAI передаётся только whitelist полей описания и платежей, не контакты и фотографии.

## Обновления и фильтрация

1. Получить полный текущий поиск и сохранить его ID.
2. Для ID без `source.json` получить detail и сохранить сырой ответ. Для известных ID использовать локальный source без запроса подробностей и перезаписи файла.
3. Построить `SourceListing` и проверить категорию, район, API-цену.
4. Использовать сохранённый результат извлечения или вызвать LLM, если результата нет.
5. Немедленно сохранить успешное извлечение до применения бизнес-фильтра.
6. Применить текущие правила к фактам; собрать подходящие объявления этого цикла.
7. Обновить экспорт и отправить только объявления без `sent`/`suppressed`.

**Fingerprint и автоматического обнаружения изменений пока нет.** Изменение описания, модели или промпта само по себе не вызывает LLM. `--reextract` принудительно скачивает свежий detail текущих объявлений и перепарсивает те, что прошли исходный фильтр. В непрерывном режиме флаг действует до завершения одного сканирования; для повторных попыток ошибок используй новый запуск с флагом. Старый успешный результат при ошибке сохраняется, но в этом цикле объявление не экспортируется и не отправляется. Следующий обычный цикл снова может использовать старый результат: для повторной перепроверки нужен `--reextract`.

При отсутствии успешного результата ошибки LLM повторяются в следующем цикле. SDK допускает до двух внутренних ретраев. Фильтры применяются каждый цикл независимо от сохранённых фактов; причин отсева и постоянной очереди в базе нет. `ScanStats` содержит счётчики и подходящие объявления текущего цикла. Известные объявления автоматически не обновляются; принудительное обновление ранее отправленных не вызывает повторного уведомления. Неудачная доставка не создаёт запись `sent`, поэтому повторяется после следующей успешной проверки.

Поиск ограничен API-ценой до LLM: объявления с общей API-ценой выше порога, но базовой арендой ниже него могут быть пропущены.

## Экспорт и факты

`data/listings.json` — массив подходящих объявлений последней завершённой проверки, каждое в формате `{source, rental}`. Внутренние состояния не экспортируются.

- `source`: ID, название, ссылка, категории, район, API-цена, до 3 фото, расстояние, даты публикации/редактирования.
- `rental.payments`: `rent_kc`, `utilities_kc`, `commission_kc`, `deposit_kc`. Все суммы в Kč. Аренда и коммунальные ежемесячные; комиссия и залог разовые. Неизвестные, неоднозначные и нулевые суммы — `null`.
- `is_room_rent=true` при явной аренде комнаты/места; категория `Pokoj` отсекается до LLM.
- `area_m2` — площадь из объявления, неизвестная — `null`.
- `available_from`: `null`, `"asap"` или дата `YYYY-MM-DD`, без угадывания неполных дат.
- `published_at`/`updated_at` берутся из `since`/`edited`; отсутствующие/невалидные — `null`.
- `distance_to_center_km` — по прямой до náměstí Svobody (49.1951, 16.6080), округление до 0,1 км; без координат — `null`.

## Telegram

Название — кликабельная ссылка. Сообщение содержит аренду и коммунальные с итогом, комиссию и залог без суммирования, заселение, расстояние и даты. HTML экранируется; название ограничено 180 символами.

Фото: максимум 3 JPEG/PNG до 10 МБ каждый. Скачиваются локально и отправляются multipart через `sendPhoto`/`sendMediaGroup`. Для `*.sdn.cz` применяется обработка `fl=res,1200,1200,1|shr,,20|jpg,80`. Неудачный снимок пропускается. Без фото или при явном отклонении загрузки (400) отправляется текст. При таймауте/ограничении частоты уведомление остаётся неотправленным.

После успешного ответа Telegram сервис сохраняет `sent`. При сбое между принятием сообщения и сохранением статуса возможны дубли: exactly-once API не предоставляет.
